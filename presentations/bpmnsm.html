Keep BPMN. Mediate meaning.

BPMNSM explores how BPMN can remain the behavioral interoperability pivot while semantic extensions, provenance, repository projections and controlled transposition connect process knowledge to standards, Enterprise Architecture and operational enactment.

CORE POSITION
Not another proprietary process metamodel.

BPMN remains BPMN. Extensions enrich. Unknown information is preserved. Views are projections. Interoperability is demonstrated through round-trip.

Why BPMNSM?

Enterprises do not have one process repository. They have overlapping corporate, CoC, programme, partner, standards-derived and application-oriented representations. The challenge is to connect them without destroying provenance or forcing premature semantic unification.

FRAGMENTATIONAggregate without flattening

Bring process fragments together while preserving source identity and unresolved references.

SEMANTICSEnrich without replacing

Attach governed semantic information to native BPMN objects through explicit extensions and external schemas.

LIFECYCLEConnect intent to operations

Explore the path from reference and generic processes through tailoring, enactment, automation and execution.

Four architectural disciplines.

BPMNSM is intentionally conservative about standards and explicit about uncertainty. These constraints are what make semantic mediation credible.

Repository interoperability starts with identity.

A repository object, a BPMN element, a business concept and a UI occurrence are not automatically the same identity. BPMNSM keeps these concerns separable so fragmented sources can be aggregated progressively.

IDENTITY

Do not guess sameness

Repository object identity, BPMN element identity and business identity serve different purposes. Source identity can retain source system, source repository and source object identifiers without overloading BPMN IDs.

The missing transition is enactment.

Publishing a generic process does not make it operational. Enactment binds process intent to a concrete organization, information landscape, application environment, control system and set of interfaces.

DESIGN-TIME

Generic process intent

Reusable behavior, generic responsibilities, control intent and collaboration semantics.

ENACTMENT-TIME

Operational realization

Concrete roles, applications, information objects, workflow tasks, programme constraints, interfaces and evidence mechanisms.

BPMNSM ↔ ArchiCG

Enterprise value

The value is not another BPMN editor. It is making process knowledge more portable, governable and operationally connected across repositories and enterprise boundaries.

Improve governanceRelate CoCs, classifications and obligations to processes.
